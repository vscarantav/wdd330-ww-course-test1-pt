S05 Tarefa: Autenticação

Visão Geral

Agora que os usuários podem fazer pedidos, você precisa criar uma maneira para a equipe revisar e processar esses pedidos. Nesta tarefa, você adicionará uma simples administrativa parte do site. Esta parte do site deve ser acessada apenas por usuários autenticados.

  2. Adicione-se à tarefa "Autenticação".
  3. Mova a tarefa para a 'Doing' lista.

Construir Página de Login do Administrador

  1. Crie um novo diretório no diretório src chamado admin.
  2. Adicione um index.html a essa pasta.
  3. Adicione o HTML básico com o cabeçalho e o rodapé do site.
  4. Crie um admin.js módulo.
  5. Adicione uma classe e dois métodos iniciais:
    1. login
    2. showLogin
  6. Termine de escrever o showLogin método.
    1. Construa um formulário de login no main elemento da página.
    2. O formulário deve incluir os seguintes elementos de formulário:
      1. e-mail,
      2. senha e
      3. um botão de envio.
    3. Quando o botão for clicado, ele deve chamar o login método.

Fazendo login

Termine o login método. O servidor com o qual você precisa se autenticar para recuperar as informações do pedido tem um endpoint de login neste endereço:

http://server-nodejs.cit.byui.edu:3000/login

Faça uma POST requisição para esse endereço com o e-mail e a senha que o usuário fornece no formulário como o corpo. Apenas para manter as coisas consistentes, vamos criar uma função em ExternalServices chamada loginRequest(creds) que fará a requisição real para o servidor. 

{ email: "user1@email.com" , password: "user1" }

Se a requisição for bem-sucedida (e-mail e senha correspondem a um usuário no banco de dados), o servidor retornará um token. Este token deve ser fornecido com cada requisição adicional que você fizer ao servidor. Salve-o como uma propriedade da Admin classe.

Se você se cansar de digitar user1@email.com você pode adicionar value="user1@email.com" ao seu elemento de entrada de e-mail e ele se lembrará disso. Lembre-se apenas de removê-lo quando terminar os testes!

Exemplo de Código para Admin.login 
constructor(outputSelector) {
  this.mainElement = document.querySelector(outputSelector);
  this.token = null;
  this.services = new ExternalServices();
}
async login(creds, next) {
  // Login method with a callback: next which makes it more flexible given that
  // there could be many different things the user wants to do after logging in.
  // This allows us that flexibility without having to write a bunch of login methods
  try {
    this.token = await this.services.loginRequest(creds);
    next();
  }
  catch(err) {
    // remember this from before?
    alertMessage(err.message.message);
  }
}

Obtendo os pedidos

Os pedidos que você está procurando podem ser encontrados em:

https://wdd330-backend-osp8.onrender.com:3000/orders

Se você fizer uma GET requisição para esse endereço, no entanto, você receberá um erro. Este é um endpoint protegido. Envie o token junto com a requisição para que o servidor saiba que você é confiável. Tokens como este são geralmente incluídos no headers da requisição.

Adicione um cabeçalho para a requisição chamado Authorization que incluirá o token. Se você olhar em ExternalServices->checkout há um exemplo de uso de um cabeçalho personalizado. Se você decidir copiar/colar esse exemplo, lembre-se de que você deseja fazer um GET, o que significa que você não deve ter uma body propriedade.

Você provavelmente vai querer criar um novo método em ExternalServices para obter os pedidos do servidor, e outro em Admin para iniciar a requisição após o login ter sido concluído com sucesso. A linha que você vai querer adicionar à parte headers das suas opções deve ser parecida com esta: 

headers: {
  'Authorization': `Bearer ${token}`
}
