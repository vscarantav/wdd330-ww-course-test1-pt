Sucesso no Curso

Visão Geral

Para ter sucesso neste curso, você precisará ser capaz de trabalhar em equipe, gerenciar seu tempo e aprender novas tecnologias rapidamente. Este documento ajudará você a entender as expectativas para o curso e como ter sucesso nele.

Resultados de Aprendizagem do Curso

Até o final deste curso, você será capaz de:

  • Tornar-se mais eficiente ao aplicar sua curiosidade e criatividade inatas.
  • Tornar-se mais hábil ao explorar seu ambiente.
  • Tornar-se uma pessoa que gosta de ajudar e aprender com os outros.
  • Usar uma abordagem de divisão e conquista para projetar soluções para problemas de programação.
  • Encontrar e solucionar bugs que você e outras pessoas terão no código que escreverem.
  • Desenvolver e depurar programas em HTML, CSS e JavaScript que usam tecnologias web de média complexidade.

Trabalhando em Equipes

A maioria dos empregos vai exigir que você trabalhe com outras pessoas. Este curso exige que você trabalhe em equipes e você deve se planejar de acordo. O objetivo é que você seja capaz de comunicar com eficácia suas ideias e dúvidas ao trabalhar com sua equipe em uma visão compartilhada.

Problemas Comuns com Grupos

A seguir estão reclamações comuns de alunos sobre trabalhar em equipes:

  • É muito difícil coordenar horários.
  • Nem todos na equipe contribuem de forma igual.
  • Nunca tenho certeza do que deveria estar fazendo.
  • É muito difícil manter todos na mesma página e fazendo a coisa certa no momento certo.
O ponto em comum para o sucesso se resume a quão bem você se comunica com os outros em sua equipe e no curso, e estar presente e fazer algo.

Dicas e Ferramentas

A coordenação de horários é provavelmente a coisa mais difícil de realizar no trabalho em equipe, dado que a maioria dos alunos não estuda em tempo integral. Durante o bloco de sete semanas, você precisará priorizar o agendamento de reuniões de equipe sincronizadas e usar as ferramentas fornecidas para ajudar sua equipe a funcionar de forma assíncrona ao longo da semana.

No início do projeto, o primeiro trabalho da equipe é se reunir e preencher a lista de Backlog. A criação dessa lista inicial REALMENTE precisa ser feita de forma síncrona (uma reunião de "todos a bordo"). Cada tarefa individual deve ser dividida em partes tão pequenas quanto faça sentido e inserida lá. (Um bom parâmetro é que a maioria das tarefas deve levar menos de 30 minutos para ser concluída.)

Sempre que alguém pensar em algo mais que precisa ser feito, isso deve ser adicionado imediatamente à lista de backlog.

Então, sempre que um membro tiver tempo para trabalhar no projeto, ele poderá fazer login no Trello, colocar sua foto em um cartão (atribuir o cartão a si mesmo) e movê-lo para Doing. Dessa forma, você sempre poderá ver quem está trabalhando em quê e o que ainda precisa ser feito.

Certifique-se de mover suas tarefas para Done quando terminar!

Um efeito colateral muito bom de trabalhar dessa forma é que, ao final do projeto, não há dúvidas sobre quem fez o quê... ou quem não fez nada.

GitHub: Toda equipe bem-sucedida precisa de uma maneira de compartilhar o que fez entre si. O GitHub é uma maneira popular de fazer isso (Bitbucket é outra alternativa popular). Essas ferramentas rastreiam alterações, o que é incrível para equipes. Elas exigem um pouco de esforço para aprender a usar de forma eficaz, mas vale totalmente a pena! Se você fizer uma pesquisa, encontrará muitos recursos gratuitos para ajudá-lo a dominá-las. (Dois tópicos aos quais dar atenção especial seriam conflitos de mesclagem e ignorar arquivos.)

Outra sugestão para gerenciar o código seria dividi-lo em pequenas partes. Distribua seu código em vários arquivos pequenos, onde cada um realiza uma única coisa, em vez de tentar juntar tudo em um único arquivo grande e difícil de manter. Isso também ajuda a evitar conflitos em códigos que já passaram por commit.

Juntando Tudo

Vamos ver como isso pode se parecer em um dia qualquer para um membro de uma equipe se você configurar seu projeto com essas ferramentas (ou algo semelhante):

  1. Faça login no Slack ou no Teams e veja quais atualizações há dos membros da equipe.
  2. Abra o Trello e revise as listas Backlog e Doing.
  3. Atribuir a mim mesmo uma nova tarefa e movê-la para Doing.
  4. Certifique-se de fazer "Pull" do repositório de código (seja no GitHub ou no Bitbucket) para obter quaisquer alterações que meus colegas de equipe possam ter finalizado.
  5. Abrir meu editor e concluir a Tarefa que peguei. (Concluir significa codificado E testado! Certifique-se de que não quebrou nada com suas alterações!)
  6. Fazer "Commit" e "Enviar" meu código de volta para o Repositório para meus colegas de equipe.
  7. Mover a tarefa que acabei de concluir no Trello para Done.
  8. Faça quaisquer atualizações no Teams que sua equipe precise saber sobre o que você fez.

Gerenciando o Fluxo de Trabalho no Front-end

O fluxo de trabalho de desenvolvimento tornou-se bastante complicado para o desenvolvimento Web. Tomemos um projeto de médio porte como exemplo. Ele pode ter dezenas de arquivos JavaScript, vários arquivos CSS, bibliotecas de terceiros e quem sabe quantos ícones, fontes, imagens, etc. envolvidos. Ele pode estar usando um pré-processador CSS como o SASS ou pode estar transpilando o JavaScript para garantir que novas funcionalidades funcionem em navegadores mais antigos.

Aqui está uma lista potencial de tarefas que podem precisar acontecer toda vez que algo mudar:

  1. Executar lint no CSS e JavaScript para encontrar quaisquer problemas de código.
  2. Executar testes unitários para garantir que nada foi quebrado com suas últimas alterações
  3. Compilar todo o SCSS/LESS para CSS
  4. Concatenar todo o CSS em um único arquivo para um carregamento mais rápido
  5. Minificar o CSS para reduzir o tamanho do arquivo
  6. Transpilar o JavaScript com o Babel para um suporte mais amplo a navegadores mais antigos
  7. Concatenar todos os arquivos JS em um único arquivo para um carregamento mais rápido
  8. Minificar e aplicar Uglify no JavaScript para reduzir o tamanho
  9. Fazer o mesmo para qualquer CSS ou JS de terceiros
  10. Mover todos os arquivos de produção para um diretório de distribuição para separá-los do material de desenvolvimento

Ufa! Essa é uma grande lista... e elas têm que acontecer MUITO!

Não é de se admirar que os desenvolvedores tenham criado ferramentas para ajudar a gerenciar tudo isso. Esta atividade apresentará uma implementação simples de algumas dessas ferramentas. As ferramentas se dividem em três categorias:

  1. Gerenciadores de pacotes: Eles rastreiam todas as dependências externas do aplicativo. Isso inclui ferramentas de desenvolvimento e bibliotecas que você pode estar usando. Ele não apenas sabe quais pacotes baixar, mas também rastreia as versões. O curso usa npm para o gerenciador de pacotes.
  2. Empacotadores: Os empacotadores lidam com a compilação, transpilação, concatenação, minificação e movimentação de arquivos no projeto. Você está usando Snowpack como empacotador. Outros empacotadores comuns são o Parcel e o Webpack.
  3. Gerenciadores de tarefas: Essas ferramentas acompanham o que precisa ser feito e quando. Geralmente haverá scripts definidos no gerenciador de tarefas para cada fase de desenvolvimento. O projeto deste curso é bastante simples, por isso usar npm é uma boa escolha. Outros gerenciadores de tarefas comuns são o Grunt ou o Gulp.

Você usará um fluxo de trabalho baseado em NPM/Node para este curso neste semestre. É importante que você entenda como essas ferramentas funcionam juntas. A Atividade em Equipe S01 orientará sua equipe na configuração desse fluxo de trabalho.
