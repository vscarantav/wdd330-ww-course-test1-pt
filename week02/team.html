S02 Atividade em Equipe: Página Dinâmica de Detalhes do Produto

Visão Geral

Esta atividade revisará as ferramentas introduzidas na semana passada e iniciará o processo de tornar a aplicação escalável, adicionando páginas de detalhes do produto geradas dinamicamente e mais organização usando Módulos ES.

Estrutura de Arquivos

Atualmente, existe um arquivo HTML para cada um dos quatro produtos de barraca no product_pages diretório. Esta organização é adequada quando há apenas alguns produtos. O plano é expandir o inventário e, portanto, esta página da web por modelo de produto não funciona.

As páginas de produtos seguem todas um layout e aparência semelhantes, portanto, deve haver apenas um arquivo HTML que carrega dinamicamente os detalhes sobre o produto solicitado.

Além disso, à medida que uma aplicação web cresce, usar Módulos ES torna-se cada vez mais importante. Os Módulos ES oferecem melhor organização e reutilização de código, que são aspectos cruciais para gerenciar projetos de software complexos.

Lembre-se de que as palavras diretório e pasta têm essencialmente o mesmo significado. Diretório é o termo mais preciso para sistemas de arquivos, enquanto pasta 📂 refere-se à metáfora gráfica que é amplamente aceita por estar altamente relacionada ao termo arquivo.

IMPORTANTE!

Certifique-se de trabalhar no src diretório ao concluir esta atividade e NÃO no dist diretório! O diretório de compilação será apagado e completamente reconstruído a cada vez que o npm run build for executado. Pense no dist como a versão de produção do seu código. src é o seu diretório de trabalho. Você não deve precisar executar npm run build com muita frequência, como uma vez por semana depois de ter mesclado algumas branches.

Quando você executa npm run start ele usará os arquivos em src para compilar o projeto.

  1. No product_pages diretório, copie uma das páginas de produto de barraca abrindo-a no editor e depois use
    File> Save As... e nomeie o arquivo index.html salvando-o no product_pages diretório.

    Este arquivo de script será programado para conter o código para produzir dinamicamente as páginas de detalhes do produto.
  3. É muito provável que outras partes da aplicação precisem fazer requisições de dados de produtos. Essa funcionalidade já foi exposta no ProductData.mjs módulo.

Revise ProductData.mjs

Abra o ProductData.mjs arquivo de módulo. Observe algumas coisas:

Clique para ver o código de exemplo (ProductData.mjs) 
function convertToJson(res) {
  if (res.ok) {
    return res.json();
  } else {
    throw new Error('Bad Response');
  }
}

export default class ProductData  {
  constructor(category) {
    this.category = category;
    this.path = `../json/${this.category}.json`;
  }
  getData() {
    return fetch(this.path)
      .then(convertToJson).then((data) => data);
  }
  async findProductById(id) {
    const products = await this.getData()
    return products.find((item) => item.Id === id);
  }
}
  1. Para tornar o módulo portátil e fácil de usar, ele usa uma classe para expor todo o código de acesso público no módulo. A classe é chamada ProductData, e ela é a exportação padrão.
  2. A ProductsDetails classe será usada para mais do que apenas barracas. Quando um nome de categoria, por exemplo, 'tents', for passado para a classe, ela irá armazená-lo e usá-lo para construir um caminho para o arquivo JSON correto. 
    this.path = `../json/${this.category}.json`;
  3. Observe o getData() método em comparação com o findProductById() método. O getData() método usa apenas promises e .then(), o findProductById() método usa async/await.

    Em geral, a sintaxe async/await é considerada mais fácil de ler (e escrever) do que o típico .then() tratamento de promises baseado em.

  4. Se a sintaxe (data) => data for confusa, dedique algum tempo lendo sobre arrow functions. Esta curta função de callback pode ser reescrita para ser como uma declaração de função anônima mais tradicional: 
    function(data) { return data; }
  5. O callback (item) => item.Id === id. Outra maneira de escrever isso poderia ser: 
    function(item) { return item.Id === id; }

    É muito comum ver funções curtas que apenas retornam algum valor ou expressão escritas usando a sintaxe de arrow function.

  6. Abra o product.js arquivo e observe que o ProductData.mjs módulo está importado. 
    import ProductData from './ProductData.js';
    E então uma instância da classe ProductData é criada. 
    const dataSource = new ProductData('tents');

    Lembre-se de que, para usar ES Modules no JavaScript, um type="module" atributo deve ser incluído na tag HTML script.

Parâmetros de URL

É necessário haver alguma maneira de passar o produto para mostrar os detalhes. Uma forma comum de fazer isso é por meio de um Parâmetro de URL ou query string. O exemplo a seguir de elemento de âncora HTML (hiperlink) tem o ID do produto incorporado ao link e chamado de "product". Quando a página carregar, ela terá acesso a essa informação.

<a href="product_pages/index.html?product=880RR" >

As seguintes instruções:

  • obtêm a parte da query string da URL atual (a parte após o ?)
  • criam um URLSearchParams objeto tornando conveniente trabalhar com os parâmetros
  • recupera esse valor do parâmetro nomeado, neste caso product
const queryString = window.location.search;
const urlParams = new URLSearchParams(queryString);
const product = urlParams.get('product')
  1. Use essas linhas para criar uma nova função no utils.mjs arquivo chamada getParam(param) que você pode usar para retornar um parâmetro da URL quando solicitado.
  2. Importe esta nova getParam função no product.js.
  3. Abra /index.html e altere o link para a primeira página de produto de href="product_pages/marmot-ajax-3.html" para href="product_pages/?product=880RR".

    De onde veio o 880RR? Procure no arquivo json/tents.json e observe que cada registro tem um valor de ID. 880RR é exatamente o ID da primeira barraca.

  4. Teste a getParam função em product.js para testar se o productId é exibido na URL quando um produto é clicado. Este seria um bom momento para testar o findProductById método também. 
    import { setLocalStorage, getParam } from './utils.mjs';
import ProductData from './ProductData.mjs';

const dataSource = new ProductData('tents');
const productId = getParam('product');

console.log(dataSource.findProductById(productId));
  5. Você também deve atualizar o restante dos links em /index.html para corresponder ao primeiro. Você pode consultar os IDs no arquivo tents.json.

ProductDetails.mjs

  1. Abra seu novo arquivo ProductDetails.mjs localizado no js diretório.
  2. Modele o arquivo ProductDetails.mjs de forma semelhante ao arquivo ProductData.mjs colocando os métodos públicos em uma classe.
    Os seguintes métodos são recomendados:
    1. constructor(): Isso é recomendado para classes.
    2. init(): Há algumas coisas que precisam acontecer antes que a classe possa ser usada. Algumas acontecerão no construtor, automaticamente. Outras precisam ser controladas e serão colocadas neste init método.
    3. addProductToCart(): Esta é a função que está atualmente em product.js.
      Mova-a para cá e observe que product.js não precisa mais importar setLocalStorage de utils.mjs.
    4. renderProductDetails(): Método para gerar ou preencher o HTML para exibir os detalhes do produto.
  3. Será interessante que o produto acompanhe informações importantes sobre si mesmo. Por exemplo, 
    constructor(productId, dataSource){
  this.productId = productId;
  this.product = {};
  this.dataSource = dataSource;
}
    Com essa informação, o produto saberá qual ID possui, terá uma fonte para obter as informações de que precisa quando chegar a hora e terá um local para armazenar os detalhes recuperados.
  4. Refatore o código de product.js para reunir tudo das últimas etapas.
    • Importe as funções necessárias neste módulo de utils.mjs, ProductData.mjs, e ProductDetails.mjs? Você pode precisar voltar para adicionar estes itens à medida que revisa os outros requisitos.
    • Obtenha o product parâmetro, o ID do produto, da URL usando a função auxiliar getParam
    • Crie uma instância da classe de dados ProductData com a URL que ela deve usar para procurar produtos.
    • Use ambas as variáveis para criar uma instância da classe ProductDetails classe
    • Chame o método init() usando a instância da classe para concluir a configuração.
    Assim que tudo estiver refatorado, o arquivo deverá ser semelhante a isto: 
    import { getParam } from './utils.mjs';
import ProductData from './ProductData.mjs';
import ProductDetails from './ProductDetails.mjs';


const productId = getParam('product');
const dataSource = new ProductData('tents');

const product = new ProductDetails(productId, dataSource);
product.init();

Conclua!

  1. Desenvolva o restante dos métodos na classe ProductDetails para fazer a seleção de produtos funcionar.
    • init(): Este método inicializador da classe precisa buscar os detalhes do produto usando a fonte de dados fornecida e renderizar os detalhes. Além disso, este método precisa gerenciar o clique do usuário no botão 'Add to Cart'.
      Use os comentários a seguir como guia no desenvolvimento deste método. 
      async init() {
// use the datasource to get the details for the current product. findProductById will return a promise! use await or .then() to process it
// the product details are needed before rendering the HTML
// once the HTML is rendered, add a listener to the Add to Cart button
// Notice the .bind(this). This callback will not work if the bind(this) is missing. Review the readings from this week on 'this' to understand why.
document.getElementById('addToCart')
  .addEventListener('click', this.addToCart.bind(this));

    • addProductToCart(): Mova esta função de product.js. Faça as alterações necessárias para fazê-la funcionar. Este método será chamado de dentro do método init().
