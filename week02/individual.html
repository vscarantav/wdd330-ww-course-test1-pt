Atividade Individual S02: Lista Dinâmica de Produtos

Visão Geral

Esta tarefa dá continuidade ao processo de tornar o site mais dinâmico, abordando a página inicial. O objetivo é listar mais produtos, exigindo que a listagem de produtos seja construída dinamicamente com base nos dados fornecidos.

Instruções

Conclua a seguinte Tarefa individualmente. Cada estudante escreverá o código para sua própria cópia.

Há vários pontos em que exemplos de código foram fornecidos. Para aproveitar ao máximo esta atividade, não olhe para os exemplos até ter tentado fazer essa seção. Depois de olhar o exemplo, resista à tentação de copiar/colar. Use os exemplos para obter correção ou ajudar a sair de um impasse. Não os use apenas para concluir rapidamente.

Ler os Dados

Nossa primeira tarefa é ler os dados do produto do tents.json arquivo (a fonte de dados atual).

  1. Importe o ProductData módulo para main.js e crie uma instância dele.

classe ProductList

  1. Crie um novo arquivo ProductList.mjs. O propósito deste script será gerar uma lista de cartões de produtos em HTML a partir de um array.
  2. Adicione um class chamado ProductList e export este class como default.
  3. Comece a criar seu ProductList módulo escrevendo o código para o construtor. Existe mais de uma categoria de produtos que precisará ser listada independentemente. Para tornar a ProductList classe o mais flexível e reutilizável possível, o construtor deve receber os seguintes parâmetros:
    1. o produto category,
    2. o dataSource, e
    3. o elemento HTML (listElement) no qual renderizar a lista de produtos (destino de saída).
  4. Por fim, use o dataSource para obter a lista de produtos com os quais trabalhar. Você pode fazer isso no construtor ou em um init() método. Uma vantagem do método init é que ele nos permitirá usar async/await ao chamar a promise em getData().
    Clique para ver o exemplo de código (ProductList.mjs) 
    export default class ProductList {
  constructor(category, dataSource, listElement) {
    // You passed in this information to make the class as reusable as possible.
    // Being able to define these things when you use the class will make it very flexible
    this.category = category;
    this.dataSource = dataSource;
    this.listElement = listElement;
  }

  async init() {
    // the dataSource will return a Promise...so you can use await to resolve it.
    const list = await this.dataSource.getData();
    // next, render the list – ** future **
  }
}
  5. Importe a ProductList classe para main.js como um tipo module.
    Certifique-se de referenciar main.js no index.html arquivo com uma script tag.
  6. Em seguida, crie uma instância da sua ProductList classe em main.js e certifique-se de que você consegue ver a lista de produtos.

Trabalhando com modelos

Ao pensar na construção da lista de produtos, cada cartão de produto terá uma marcação muito semelhante. Os modelos são uma forma de reutilizarmos a marcação de maneira eficiente. Antes você podia deixar a marcação no arquivo HTML e apenas preencher os valores com JavaScript, mas isso não funcionará pois você precisa de várias cópias do modelo. Existem muitas maneiras pelas quais os desenvolvedores lidam com questões de modelos.

Ao escolher uma solução de modelo, tenha algumas coisas em mente:

  1. Idealmente, a solução manterá a separação de conceitos. Seria bom se você deixasse o HTML onde ele pertence, no arquivo .html em vez de enterrado no JavaScript. Isso leva a um código mais fácil de manter.
  2. O HTML e o CSS de um site são frequentemente gerenciados por uma equipe diferente da lógica no JavaScript. Se o HTML estiver no JavaScript, toda vez que uma alteração de estilo precisar ser feita, o JavaScript terá que ser modificado em vez de apenas alterar o HTML. Se a sua solução de modelos envolve incorporar o HTML no código JavaScript, isso é feito de tal forma que não exija um alto nível de conhecimento de JS para alterar um modelo?
  3. Desempenho. Nossa solução de modelos não deve levar a problemas de desempenho.

Algumas das opções que são usadas podem ser encontradas abaixo e são ensinadas na pilha de cursos do programa de graduação:

  • Framework ou Biblioteca: Se o projeto estiver usando um framework ou biblioteca front-end como React, Angular, Vue, Svelte. O framework ou biblioteca terá a solução de modelos integrada.
  • Renderização no Lado do Servidor (SSR): Você poderia usar uma linguagem ou framework no lado do servidor como PHP, .NET ou NodeJS para inserir o modelo quando a página fosse requisitada, mas antes de ser enviada.
  • Ferramentas de Modelos: Existem soluções de modelos que se tornam parte do processo de compilação do front-end. Ferramentas como Handlebars, Nunjucks, pug, e outros motores. A maioria dessas ferramentas seria integrada ao seu fluxo de trabalho por meio do seu empacotador ou gerenciador de tarefas.
  • Modelo HTML: Use a tag <template> em HTML com um pouco de JavaScript para construir sua própria solução.
  • Literal de Modelo: Use strings de literal de modelo em JavaScript para construir sua própria solução.
  1. Como as necessidades de modelos são bem simples, você optará por uma das soluções de modelos mais simples da lista, strings de literal de modelo. Algumas das outras opções oferecem mais funcionalidade e, em alguns casos, melhor escalabilidade, mas ao custo de mais complexidade.
  2. Crie uma função de modelo que simplesmente retornará uma string de literal de modelo para cada um dos modelos necessários. No topo do seu ProductList módulo, adicione uma função para um productCardTemplate(product). Você pode usar o HTML atual no arquivo /index.html como seu ponto de partida.
    productCardTemplate() exemplo 
    // ProductList.mjs
function productCardTemplate(product) {
  return `<li class="product-card">
    <a href="product_pages/?product=">
      <img src="" alt="Image of ">
      <h2 class="card__brand"></h2>
      <h3 class="card__name"></h3>
      <p class="product-card__price">$</p>
    </a>
  </li>`
}
  3. Adicione um método à sua classe ProductList para usar este modelo chamado renderList, chame a função de modelo uma vez para cada produto na lista e insira-o no DOM. O método deve receber a lista de produtos como um argumento.

    Lembre-se: map é uma ótima maneira de transformar objetos de dados em strings HTML.

Adicionando os dados

  1. Você deve ter alguns cartões de produtos sendo exibidos, mas todos são iguais e estão faltando informações críticas. A próxima etapa é inserir as informações específicas do produto no modelo HTML. É por isso que você usou uma string de literal de modelo, para aproveitar a interpolação de variáveis que ela oferece.
  2. Insira as variáveis corretas em seu modelo. Em seguida, teste novamente para garantir que tudo esteja sendo exibido corretamente. Lembre-se de remover os produtos codificados diretamente no arquivo /index.html para que você não tenha nenhum duplicado.

Tornar renderList reutilizável

O código para o seu renderList método se parece com isto:

renderList(list) {
  const htmlStrings = list.map(productCardTemplate);
  this.listElement.insertAdjacentHTML('afterbegin', htmlStrings.join(''));
}

Você precisará gerar mais conteúdo com este modelo HTML em outras partes do programa. Para tornar esta função reutilizável, primeiro examine todas as partes do código que são específicas para este caso de uso específico, que é criar uma lista de cartões de produtos.

  1. 1️⃣ O elemento no qual você deseja inserir o novo HTML está sendo fornecido pela classe: this.listElement.
  2. 2️⃣ A função de modelo que você usará está codificada diretamente: productCardTemplate
  3. 3️⃣ Você também codificou diretamente a posição do HTML inserido: afterbegin, este nem sempre pode ser o caso desejado. Às vezes, você também pode querer limpar o conteúdo do elemento primeiro.

A lista de produtos também é específica, mas você já está passando isso.

  1. Lidar com os itens 1️⃣ e 3️⃣ é fácil porque você pode simplesmente passar esses valores para a função como parâmetros.
  2. O item 2️⃣, no entanto, é uma função. Funções podem ser passadas para outras funções em JavaScript. Crie uma nova função no arquivo utils.mjs chamado renderListWithTemplate e exporte-a.
    1. Ela deve receber cinco (5) argumentos: templateFn, parentElement, list, position, and clear.
    2. Em seguida, mova o código da sua renderList função para esta nova função exportada em utils.mjs e refatore o código para funcionar com estes novos parâmetros.
  3. Frequentemente afterbegin será a posição na qual você deseja inserir e, frequentemente, podemos não querer limpar o conteúdo. Quando você declarar sua função, defina um valor padrão para esses dois parâmetros. 
    function renderListWithTemplate(templateFn, parentElement, list, position = "afterbegin", clear = false)
  4. Adicione a lógica à sua função para limpar o elemento fornecido se clear for verdadeiro.
  5. Em seguida, importe em sua função para o ProductList módulo e refatore renderList para usar a nova função utilitária.
