S01 – Atividade de Aprendizagem: Fluxo de Trabalho

Visão Geral

Um fluxo de trabalho moderno de desenvolvimento web front-end otimiza como sites e aplicações são construídos e gerenciados. Mesmo para um projeto de porte médio, é provável que você tenha que lidar com inúmeros arquivos JavaScript ou TypeScript, várias folhas de estilo CSS e uma variedade de recursos, como ícones, fontes e imagens.

Muitos projetos agora se baseiam em arquiteturas baseadas em componentes usando frameworks como React, Angular ou Vue.js. Esta aula não usará nenhum framework. No entanto, o conceito de arquitetura de projeto é importante. Nesta aula, você será apresentado ao Vite (pronuncia-se como "veet"), um empacotador de módulos JavaScript, que agrupa arquivos para um desempenho ideal e lida com tarefas de projetos de desenvolvimento web.

Preparação

A seguir está uma lista simplificada, mas prática, de tarefas que devem ocorrer toda vez que algo muda em um projeto de desenvolvimento de aplicação web. Isso reflete o fluxo de trabalho típico para manter a qualidade do código, a funcionalidade e a consistência da implantação.

  • Atualizar a documentação, como o README ou outros documentos específicos de funcionalidades aplicáveis
  • Executar testes unitários de componentes e funcionais.
  • Executar testes de integração para garantir que todos os componentes funcionem juntos.
  • Executar testes de ponta a ponta para simular interações do usuário e garantir que a aplicação se comporte como esperado.
  • Executar formatador de código, linter e verificar outros problemas de qualidade de código.
  • Fazer auditoria para verificar pacotes desatualizados ou vulneráveis.
  • Verificar a acessibilidade e a responsividade.
  • Concatenar CSS em um único arquivo para um carregamento mais rápido.
  • Minificar o CSS para reduzir o tamanho do arquivo.
  • Transpilar o JavaScript com o Babel para um suporte mais amplo a navegadores antigos.
  • Concatenar todos os arquivos JS em um único arquivo para um carregamento mais rápido.
  • Minificar e aplicar Uglify no JavaScript para reduzir o tamanho.
  • Fazer o mesmo para qualquer CSS ou JS de terceiros.
  • Mover todos os recursos de produção para um diretório de distribuição para separá-los do material de desenvolvimento.
  • Implantar a aplicação em um ambiente de teste (staging) para os testes finais.

As ferramentas de operações de desenvolvimento e tarefas de implantação dividem-se em três categorias:

  1. Gerenciadores de pacotes: Estes mantêm o controle de todas as dependências externas da aplicação. Isso inclui ferramentas de desenvolvimento e bibliotecas que são usadas. Ele não apenas sabe quais pacotes baixar, mas também rastreia as versões. Você está usando npm como gerenciador de pacotes.
  2. Empacotadores: : Os empacotadores lidam com a compilação, transpilação, concatenação, minificação e movimentação de recursos no projeto. Você está usando Vite como o empacotador. Outros empacotadores comuns são Snowpack, Parcel e Webpack.
  3. Gerenciadores/executores de tarefas: Estes mantêm o controle do que precisa ser feito e quando. Geralmente haverá scripts definidos no gerenciador de tarefas para cada fase do desenvolvimento. O projeto é bastante simples, por isso usar npm novamente como gerenciador de tarefas é suficiente. Outros gerenciadores comuns são o Grunt ou o Gulp.

    Embora o npm em si seja primariamente um gerenciador de pacotes, sua capacidade de definir e executar scripts, combinada com a disponibilidade de pacotes específicos para tarefas, torna-o uma ferramenta valiosa para o gerenciamento de tarefas no desenvolvimento de software. Ele oferece uma maneira simples e eficiente de automatizar tarefas repetitivas e otimizar seu fluxo de trabalho.
