S04 Atividade em Equipe: Checkout

Visão Geral

A próxima etapa para o site é construir o processo de checkout.

Instruções da Atividade

Conclua a seguinte tarefa em equipe. Designe um membro da equipe como o "condutor principal" e colaborem em sua cópia do código. Todos na equipe devem estar ativamente engajados na escrita do código e na contribuição para a solução. Assim que a solução estiver funcionando, garanta que todos na equipe obtenham uma cópia do código.

Há muitos pontos onde exemplos de código foram fornecidos. Para aproveitar ao máximo esta atividade, não olhe para os exemplos até que sua equipe tenha tentado essa seção. Depois de olhar o exemplo, resista à tentação de copiar/colar. Use os exemplos para obter correções ou para ajudar a sair do impasse.

Trello

  1. Na reunião síncrona, o condutor deve visitar a cópia da equipe do quadro do Trello do projeto.
  2. Adicione cada um dos membros da equipe presentes ao Team Activity 04: Checkout cartão.
  3. Mova-o para a "Doing" lista no Trello.

Branch do GitHub

O Carrinho

Verifique a página do seu carrinho para ter certeza de que ela está exibindo o total corretamente.

Se não estiver, alguém da sua equipe deve concluir esse cartão no Trello.

      1. Endereço
      2. Cidade

      4. CEP
    3. Pagamento
      1. Número do Cartão de Crédito
      2. Data de Validade
      3. Código de Segurança
    4. Botão de Checkout
  3. O formulário não deve ser enviado a menos que todos os campos estejam preenchidos.
  4. Inclua um resumo do pedido em algum lugar próximo ao formulário que inclua:
    • Subtotal
    • Imposto
    • Estimativa de Frete
    • Total do Pedido

    Em um site real, o servidor também deve verificar os totais para garantir que o usuário não tente nenhuma malandragem.

Resumo do Pedido

  1. Preencha as informações na seção de resumo do pedido.
    ✔ O valor subtotal dos itens virá dos itens no carrinho.
    ✔ Adicione o imposto e depois os custos de frete.
    ✔ Calcule o total do pedido.

    Normalmente, o imposto e o frete seriam calculados de acordo com o endereço de destino. Haveria um processo de consulta que descobriria os valores corretos a serem usados. Para manter a simplicidade, use as mesmas fórmulas para todos os pedidos.

    Imposto: Use 6% de imposto sobre vendas no valor subtotal.
    Frete: Use $10 para o primeiro item mais $2 para cada item adicional depois disso.

  3. Exporte uma classe padrão chamada CheckoutProcess módulo.

  5. Em CheckoutProcess, crie outro método para calcular e exibir impostos, frete e o total do pedido. Este método deve ser chamado após o usuário preencher o CEP.

Refatorar ProductData

Use o mesmo servidor das semanas anteriores para obter os produtos para enviar os pedidos, no entanto, há um endpoint diferente. A URL é:

https://wdd330-backend-osp8.onrender.com/checkout

Observe que, como os dados agora estão sendo enviados para o servidor, uma POST requisição é necessária em vez de uma GET requisição.

O ProductData módulo está fazendo requisições para o servidor no momento e, portanto, este seria o local lógico para adicionar a funcionalidade de enviar um pedido. No entanto, o nome "ProductData" torna-se menos descritivo do que está acontecendo no módulo. Seria mais descritivo nomeá-lo como ExternalServices.

Se você entrou um pouco em pânico quando leu isso, significa que está prestando atenção. Renomear algo que você já usou em vários lugares não é algo a se fazer levianamente, mas às vezes é necessário. Por conta disso, boas ferramentas de desenvolvimento, como o VS Code, possuem formas integradas de auxiliar no desenvolvimento.

  1. Faça commit e envie suas alterações antes de prosseguir. Isso facilitará a reversão se algo der errado.
  2. Abra ProductData.mjs e selecione a palavra ProductData na definição da classe. Clique com o botão direito sobre ela e selecione Renomear símbolo no menu.
  3. Digite "ExternalServices" e mantenha pressionada a tecla ctrl enquanto pressiona enter/return (ou qualquer combinação de teclas que o menu suspenso indicar) para pré-visualizar a alteração. Um novo painel chamado Pré-visualização da Refatoração será aberto no editor e exibirá todas as instâncias em que o nome precisará ser alterado. Clique com o botão esquerdo do mouse em uma das linhas e isso abrirá o arquivo mostrando a alteração proposta. Clicar em Aplicar no painel enviará a alteração. Revise cada alteração e faça as atualizações conforme necessário.
  4. Em seguida, renomeie o arquivo do módulo para que ele reflita a alteração. Se você clicar com o botão direito no arquivo no Explorador de Arquivos e selecionar renomear, deverá receber uma mensagem pop-up perguntando se também deseja renomear as importações. Diga que sim e selecione File->Save All novamente.
  5. Finalmente, apenas para ter certeza de que nada foi esquecido, vá para a Barra de Atividades na lateral da janela do seu VS Code e clique no ícone Pesquisar (lupa 🔎) (ctrl/cmd + shift + F). Digite ProductData e se houver mais alguma instância, altere-a.
  6. Teste as páginas de lista de produtos e detalhes do produto para garantir que ainda funcionem.

Enviar o Pedido – CheckoutProcess

O processo de checkout envolverá um servidor. Ele espera que enviemos a ele um objeto com todas as informações sobre o pedido em um formato específico. O objeto deve se parecer com o seguinte (a ordem dos campos não importa):

{
  orderDate: '2021-01-27T18:18:26.095Z',
  fname: "John",
  lname: "Doe",
  street: "123 Main",
  city: "Rexburg",
  state: "ID",
  zip: "83440",
  cardNumber: "1234123412341234",
  expiration: "8/21",
  code: "123",
  items: [{
    id: "20CXG"
    name: "The North Face Pivoter 27 L Backpack"
    price: 39.99,
    quantity: 1
  }, {
    id: "14GVF",
    name: "Marmot 5°F Rampart Down Sleeping Bag - 650 Fill, Mummy (For Men and Women)",
    price: 229.99,
    quantity: 1
  }],
  orderTotal: "298.18",
  shipping: 12,
  tax: "16.20"
}

Observe que as chaves no seu objeto DEVEM corresponder às chaves mostradas acima. Você não pode enviar "firstName". Deve ser "fname". É isso que o servidor estará esperando. Verifique seus nomes no formulário HTML se houver diferenças.

    // takes a form element and returns an object where the key is the "name" of the form input.
function formDataToJSON(formElement) {
  const formData = new FormData(formElement),
    convertedJSON = {};

  formData.forEach(function (value, key) {
    convertedJSON[key] = value;
  });

  return convertedJSON;
}
  3. Use 1234123412341234 para o número do cartão, 123 para o código de segurança e qualquer data de expiração no futuro se desejar que seu pedido seja concluído com sucesso.

    Para os testes, para economizar tempo e digitação, lembre-se de que você pode definir a value="" propriedade de um elemento de entrada HTML. Lembre-se de remover seus valores padrão assim que tudo estiver funcionando.

  4. O método deve fazer um POST desse objeto. Você precisará criar um objeto de opções personalizado e passá-lo com o seu fetch. (Lembre-se de converter seu objeto para string antes de enviá-lo!) para o endereço acima (https://wdd330-backend-osp8.onrender.com/checkout) e retornar a resposta do servidor. A resposta será JSON.

    Todas as requisições feitas até agora foram bastante simples e as configurações padrão para o fetch foram suficientes. As configurações padrão não funcionarão para nós aqui. O Fetch possui um segundo argumento opcional que é para opções. Um objeto de opções que funcionará para uso aqui está abaixo:

    const options = {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(payload)}

    Isso pode ser usado assim:

    fetch(url, options);

    As escolhas incluem observar um click evento no botão do formulário, ou observar um submit evento no formulário.

  5. Qualquer que seja sua escolha, você vai querer evitar que o formulário faça o que normalmente faria no envio. Você pode fazer isso chamando event.preventDefault() na função listener.
  6. Você pode considerar esta atividade concluída quando receber uma resposta do seu POST para o servidor. A próxima atividade continuará isso lidando adequadamente com as respostas de sucesso e falha.
