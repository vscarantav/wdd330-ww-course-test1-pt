S04 – Projeto: Final – Proposta

Visão Geral

Defina uma ideia para o seu projeto final de aplicação web. Esta semana, uma detalhada proposta de projeto é necessária. Esta proposta ajudará você a solidificar sua ideia e a planejar o projeto. Ela também ajudará você a entender o escopo do projeto em relação à quantidade de tempo necessária para concluir a aplicação web até o final do semestre.

Você NÃO tem permissão para usar openweathermap.org/api da WDD 231 como um dos seus dois serviços de API obrigatórios.

Instruções

Descrição e Requisitos do Projeto

  1. Revise a descrição do projeto e os requisitos de desenvolvimento: Projeto Final de Aplicação Web

Escreva o Documento de Proposta

Definitivamente NÃO use qualquer agente ou serviço de IA para escrever sua proposta. Você deve apresentar sua proposta de aplicação de forma ponderada e sucinta, de acordo com as seções obrigatórias listadas abaixo. Conteúdo gerado por IA não será aceito e resultará em nota zero para esta Tarefa.

Seções obrigatórias no documento de proposta:

  1. Visão Geral: Uma breve descrição do projeto. Qual é o problema que você está tentando resolver? Qual é a sua motivação para trabalhar nisso?
  2. Público-Alvo: Quem é o público-alvo da aplicação? A quem ela atenderá?
  3. Funções Principais: Uma lista das funções principais da aplicação. O que ela fará? Liste-as com o máximo de detalhes possível. São necessárias pelo menos 8 funções principais com suas descrições.
  4. Wireframes: Wireframes das visões principais, móvel e desktop.
  5. Dados Externos: Qual(is) fonte(s) de dados de API externa(s) você usará? Quais dados você precisará armazenar?
  6. Lista de Módulos: Uma lista dos módulos que você precisará construir. Quais são os principais componentes da aplicação?
  7. Identidade Gráfica: Liste o esquema de cores, tipografia e outros detalhes específicos de estilo de elementos. Inclua um design ou descrição para um ícone da aplicação.
  8. Cronograma: Um cronograma do trabalho que você está planejamento concluir para as semanas 5 a 7 do semestre. Inclua entregáveis específicos de cada semana.
  9. Planejamento do Projeto: Um link para um quadro do Trello com todas as tarefas em que você puder pensar neste momento definidas como cartões. Novamente, seja o mais detalhado possível aqui.

    Embora você deva se esforçar para ser minucioso em seu planejamento inicial, entenda que o quadro do Trello do seu projeto é um documento vivo que será continuamente atualizado e refinado. Não busque a perfeição no início, mas concentre-se em capturar as tarefas essenciais e adaptar-se à medida que seu projeto avança.

  10. Desafios: Quais você antecipa que serão os maiores desafios ao construir esta aplicação?

Avaliação por Pares

  2. Revise as propostas dos seus colegas que publicaram.
  3. Forneça feedback apropriado. Peça esclarecimentos onde necessário.
